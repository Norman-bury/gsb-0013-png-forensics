# PNG 取证修复

## 输入

`damaged.png` 是一张被多处破坏的 PNG。坏的地方一共这几类：

- 文件头 8 字节签名被清零
- IHDR 块里记录的宽和高被篡改，导致这个块的 CRC 对不上
- IDAT 数据块被重新排了顺序
- 有一段字节跟一个未知的单字节密钥做了异或
- 另外几个块的 CRC 值本身就是错的

这张图是从一张合法的 32x24 RGB 图派生出来的，正确修复后应当能通过任何标准 PNG 校验器。

## 你要交付什么

写一个 `solve.py`，命令行约定：

```bash
python3 solve.py <输入.png> <输出.png>
```

读入损坏的 PNG，写出修复后的 PNG。

再交一份 `report.md`，把每一处损伤讲清楚：在哪个位置、属于哪种损伤、你凭什么判定它坏了、用什么方法修好的。判定依据和修复方式要连成一条证据链，不能瞎猜。

## 判分标准（`grade.py`）

```bash
python3 grade.py
```

`grade.py` 会先跑 `solve.py damaged.png <临时文件>` 生成修复结果，再逐项校验：

- 文件头 8 字节签名正确
- 每个 chunk 的 CRC32 与重算值一致
- IHDR 宽 32 高 24，位深 8，颜色类型 2（RGB），压缩、滤波、隔行都为 0
- 所有 IDAT 数据按序拼接后 zlib 解压成功，解压出的裸像素流与原图逐字节一致
- 最后一个 chunk 是空数据的 IEND

全部通过输出 `PASS`，退出码 0；任何一项不过输出 `FAIL`，退出码非 0。

你可以自己先跑 `python3 grade.py` 自测，过了再交。`report.md` 不在自动判分里，由人工复核证据链。

## 约束

- 全程本地离线，不装第三方库，只许用标准库（`struct`、`zlib`、`binascii` 这些都在标准库内）。
- 不能用现成的 PNG 修复工具，格式解析、CRC 重算、zlib 解压都得自己写。
- PNG 是自带校验的结构化格式，签名、每个块重算出来的 CRC、IDAT 解压出的流能不能对上 IHDR 里记录的尺寸，这些校验值本身就是定位损伤的线索，别把它们当成障碍。
